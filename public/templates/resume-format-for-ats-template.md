# ATS-Safe Resume Skeleton
### A free one-pager from AdaptiveResume

Build on this structure and the parse comes out clean. One column, top to bottom, real text throughout.

## The skeleton

**[Your Name]**
[City, State] · [Phone] · [Email] · [LinkedIn URL]
*(in the document body — never the page header)*

**SUMMARY**
2–3 lines: what you are, how long you've done it, what you're strongest at.

**EXPERIENCE**
**[Job Title]** — [Employer], [City, State]
[MM/YYYY] – [MM/YYYY]
- [What you did + honest scale: volume, team size, systems]
- [3–5 bullets per recent role; fewer for older ones]

*(repeat per job, newest first — always one column)*

**SKILLS**
[Plain-text list, comma- or bullet-separated. Real terms from your work — no graphics, no rating bars.]

**EDUCATION**
[Degree/Diploma] — [School], [Year if recent]

**CERTIFICATIONS**
[Full name (Acronym) — Issuer, date or current-through]

## The rules this skeleton bakes in
| Element | Do | Because |
|---------|----|---------|
| Layout | One column | Multi-column work history can scramble which dates go with which job |
| Headings | Summary / Experience / Skills / Education / Certifications | Parsers are trained on the standard names |
| Contact info | In the body | Some parsers skip headers/footers entirely |
| File | .docx, or text-based PDF | Image-only PDFs contain no text to read |
| Dates | Month + year, same format throughout | Lets tenure be computed correctly |
| Tables / text boxes / icons | None | Read wrong, out of order, or not at all |

## Quick self-test
Select-all and copy your finished file into a plain-text editor. If your jobs, titles, dates, and contact info come through legible and in order — a parser will read it fine. If it's scrambled or missing pieces, fix the layout, not the words.

## What formatting can't do
Clean parsing doesn't rank you above anyone — it just guarantees the system sees what's actually there. The content still has to be true and specific.
